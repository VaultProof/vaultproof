Your vp_live_ key is safe to share in prompts and configs

A vp_live_ key is a proxy key, not your real API key. Even if it appears in your code, prompts, chat history, or AI agent context, your actual provider keys (OpenAI, Anthropic, etc.) remain protected. The proxy key can only be used to make API calls through VaultProof — and you can revoke it, set budget caps, or hit the kill switch from your dashboard at any time.

MCP

MCP Server

Connect any MCP-compatible AI assistant to VaultProof — manage keys and proxy calls via the Model Context Protocol.

What is MCP?

The Model Context Protocol lets AI assistants connect to external tools and services. VaultProof's MCP server lets any compatible AI assistant store keys, check usage, and make proxied API calls — all authenticated via OAuth.

Available tools:

list-keys

List your stored API keys

store-key

Store a new key with split encryption

get-usage

Check usage stats and limits

proxy-request

Proxy an API call through VaultProof

Setup

1
Add VaultProof to your MCP client config
Claude Desktop — claude_desktop_config.json
{
  "mcpServers": {
    "vaultproof": {
      "url": "https://mcp.vaultproof.dev/mcp"
    }
  }
}
Claude Code — settings or .mcp.json
{
  "mcpServers": {
    "vaultproof": {
      "type": "url",
      "url": "https://mcp.vaultproof.dev/mcp"
    }
  }
}
2
Authenticate
On first use, your AI assistant will open a browser window for you to log in with your VaultProof account. This uses OAuth 2.1 with PKCE — your password is never shared with the AI assistant.
3
Use VaultProof tools
Once connected, your AI assistant can store keys, check usage, and proxy API calls through VaultProof. Ask it to "store my OpenAI key in VaultProof" or "check my VaultProof usage."

Server URL

https://mcp.vaultproof.dev/mcp

OAuth metadata: https://mcp.vaultproof.dev/.well-known/oauth-authorization-server

Works with any MCP client

CC

Claude Code + VaultProof

Claude Code reads your environment variables — including your real API keys. Two changes to your shell config and it only ever sees a proxy key.

2-minute setup No code changes required Works with any provider Free tier: 10K calls/month

Claude Code makes API calls using whatever ANTHROPIC_API_KEY is set in your environment. With VaultProof, that value is a vp_live_ proxy key — not your real Anthropic key. The proxy call goes through VaultProof, your actual key is reassembled briefly in memory, the call is made, and the key is wiped. Claude Code gets the response. Nothing is stored.

Prerequisites

  • ✓ A VaultProof account — free, no credit card
  • ✓ Node.js installed (for the CLI)
  • ✓ Claude Code installed and working
  • ✓ An Anthropic API key to protect
1
Install the VaultProof CLI
bash
npm install -g @vaultproof/cli
vaultproof --version
2
Connect to your account
bash
vaultproof test
# ✔ Connected — 0 keys stored
3
Store your Anthropic API key
The CLI will prompt you to paste your key.
bash
vaultproof store -p anthropic
# Paste your Anthropic key when prompted
4
Update your shell environment
Remove any existing ANTHROPIC_API_KEY line from your shell config and add these two lines.
~/.zshrc (or ~/.bashrc)
export ANTHROPIC_BASE_URL=https://api.vaultproof.dev/v1/anthropic
export ANTHROPIC_API_KEY=vp_live_your_key_here
bash
source ~/.zshrc
5
Run Claude Code normally
Nothing changes in your workflow. Claude Code works exactly as before.
bash
claude

What happens on each call

1. Claude Code sends request using your vp_live_ key
2. VaultProof reassembles your real key briefly in memory
3. Real API call is made (SSE streaming supported)
4. Key is wiped from memory

What Claude Code can and can't do

Can do

  • ✓ Make completions and embeddings
  • ✓ Use streaming responses
  • ✓ Read the vp_live_ key

Can't do

  • ✗ Read your real Anthropic key
  • ✗ Exceed your budget cap
  • ✗ Continue after kill switch

AI Providers (OpenAI, Anthropic, etc.)

Same setup for every AI tool — change the base URL and use your vp_live_ key

Every AI provider works the same way. Two changes: swap the base URL, use your vp_live_ key as the API key.

bash — Claude Code, Windsurf, any CLI tool
export ANTHROPIC_BASE_URL=https://api.vaultproof.dev/v1/anthropic
export ANTHROPIC_API_KEY=vp_live_your_key_here
python — OpenAI SDK
client = openai.OpenAI(
    api_key="vp_live_your_key_here",
    base_url="https://api.vaultproof.dev/v1/openai"
)
python — Anthropic SDK
client = anthropic.Anthropic(
    api_key="vp_live_your_key_here",
    base_url="https://api.vaultproof.dev/v1/anthropic"
)
json — Cursor, Continue.dev, or any OpenAI-compatible tool
{
  "apiBase": "https://api.vaultproof.dev/v1/openai",
  "apiKey": "vp_live_your_key_here"
}
bash — cURL or any HTTP client
curl https://api.vaultproof.dev/v1/openai/v1/chat/completions \
  -H "Authorization: Bearer vp_live_your_key_here" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4","messages":[{"role":"user","content":"Hello"}]}'

Supported providers

OpenAI, Anthropic, Google AI, Mistral, Cohere, Groq, Perplexity, DeepSeek, Fireworks, Together.ai, Replicate. The URL pattern is always https://api.vaultproof.dev/v1/{provider}.

Getting an IP restriction error?

If your API key has IP restrictions, the proxy call comes from VaultProof's server, not yours. Remove the IP restriction on your key and rely on VaultProof's per-key rate limits and budget caps instead.

Other SDKs (Stripe, AWS, Supabase, etc.)

For providers that don't use a base URL — proxy calls through the server

Use vault.proxy() to make API calls through VaultProof's server. Your key is not exposed to the client code.

CLI

bash
# Store your key
vaultproof store -p stripe -l "secret"

# Proxy the API call through VaultProof (key stays out of your code)
vaultproof proxy -k <keyId> --path /v1/charges -d '{"amount":2000,"currency":"usd"}'

SDK

javascript
import VaultProof from '@vaultproof/sdk';

const vault = new VaultProof(process.env.VAULTPROOF_API_KEY);

// Proxy through VaultProof -- key stays out of your codebase
const result = await vault.proxy('your-stripe-key-id', '/v1/charges', {
  amount: 2000, currency: 'usd'
});
VP

Production App (Vercel, Netlify, etc.)

Remove all secrets from your hosting — only keep VAULTPROOF_API_KEY

1
Install the SDK and CLI
bash
npm install @vaultproof/sdk
npm install -g @vaultproof/cli
2
Test your connection
Verify your API key works before storing anything.
bash
vaultproof test
# ✔ Connected — 0 keys stored
3
Run migrate from your project directory
It reads your .env, asks which secrets to store, and prints everything you need.
bash
vaultproof migrate

What this does:

  • • Reads your .env (only key names and values — nothing else is scanned)
  • • Separates secrets from config (e.g. STRIPE_SECRET_KEY vs NEXT_PUBLIC_APP_URL)
  • • Asks you one-by-one which secrets to store
  • • Stores them in VaultProof via split-key encryption
  • • Prints a ready-to-use lib/vault.ts helper
  • • Prints which env vars to remove from your hosting

Does NOT modify any files. Everything is printed to your terminal for you to copy.

Your code is scanned locally on your machine by the CLI. No source code leaves your device. Only the key values you choose to store are sent to VaultProof for split-key encryption.

4
Copy the vault.ts helper into your project
The migrate command prints this — paste it into lib/vault.ts.
5
Replace process.env.X in your server code
Every file that reads a secret needs to change. This is the bulk of the work.
Before (secret in .env)
import Stripe from 'stripe';
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!);
After (secret from VaultProof)
import Stripe from 'stripe';
import { getSecret } from '@/lib/vault';

const stripe = new Stripe(await getSecret('STRIPE_SECRET_KEY'));
6
Update your hosting env vars
Remove every secret. Keep only non-secret config and your VaultProof key.
Vercel / Netlify / .env
# Keep — this is your only secret
VAULTPROOF_API_KEY=vp_live_your_key_here

# Keep — these are config, not secrets
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_APP_URL=https://yourapp.com

# DELETE all of these — they now come from VaultProof
# STRIPE_SECRET_KEY=sk_live_...
# SUPABASE_SERVICE_ROLE_KEY=eyJ...
# SMTP_PASSWORD=...
7
Test locally, then deploy
Make sure every feature that touches a secret still works.
bash
# Test locally with only VAULTPROOF_API_KEY set
VAULTPROOF_API_KEY=vp_live_... npm run dev

# Check: payments work? auth works? emails send?
# Then deploy as normal

What about latency?

Each getSecret() call adds ~100–200ms for the round trip. This happens once per request, and the key is only in memory for the duration of that request. For most apps (payments, auth, emails) this is unnoticeable.

Key Rotation

Rotate your keys with zero downtime — one click, no code changes.

Why rotate?

  • • Your key was exposed in a commit, log, or AI chat
  • • An employee or contractor with access left
  • • Regular security hygiene (rotate every 90 days)
  • • You hit a suspicious spike in usage

Rotating your real API key (e.g., OpenAI)

1
Generate a new key at your provider's dashboard
Go to OpenAI, Anthropic, Google, Stripe, etc. and create a fresh key.
2
Go to VaultProof → Keys → click "Rotate" on the key
3
Paste the new key
It is split and encrypted instantly.
4
Done. Every app using your vp_live_ key automatically uses the new provider key. No code changes, no redeployments.

Rotating your vp_live_ developer key

1
Go to VaultProof → Keys → Developer Keys section
2
Click "Rotate" on the key you want to change
3
Copy the new vp_live_ key
Update it in your .env file.
4
The old key stops working immediately

The key advantage

Since your apps only use vp_live_ keys, rotating the underlying provider key requires zero code changes. This is the whole point of the proxy.
